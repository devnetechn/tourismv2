# Maasim — Discover the Coast. Experience the Culture.

An independent tourism website concept for **Maasim, Sarangani Province, Philippines**, built with Next.js, TypeScript, and Tailwind CSS.

> This is a proposed creative direction. It is not an official website of the Municipal Government of Maasim, and the tagline has not been adopted by the municipality.

## Requirements

- Windows 10/11, macOS, or Linux
- [Node.js](https://nodejs.org/) 20.9 or newer (developed on Node 24) with npm
- An internet connection the first time you build, so Next.js can download the Google Fonts it self-hosts

No Docker, database, API keys, or paid services are needed.

## Run it on Windows

Open **PowerShell** or **Command Prompt** in the project folder:

```powershell
npm install
npm run dev
```

Then open <http://localhost:3000>.

> **PowerShell error "running scripts is disabled on this system"?** Windows is blocking npm's PowerShell wrapper. Either run `npm.cmd run dev` (and `npm.cmd install`, `npm.cmd run build`), use Command Prompt instead, or allow local scripts once for your account:
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```

### Production build

```powershell
npm run build
npm run start
```

### Checks

```powershell
npm run lint
npx tsc --noEmit
```

`npx tsc --noEmit` needs route types, which are generated by `npm run dev`, `npm run build`, or `npx next typegen`.

## Configuration

Copy `.env.example` to `.env.local` and set `NEXT_PUBLIC_SITE_URL` to the public address before you deploy. It controls canonical URLs, Open Graph tags, the sitemap, and robots.txt. Without it the site uses `http://localhost:3000`.

Contact details and social links live in `src/data/site.ts`. Social links with `href: null` are hidden, and the footer shows a "to be confirmed" note instead.

## Routes

| Route | Page |
| --- | --- |
| `/` | Homepage |
| `/destinations` | Destination search and category filters |
| `/destinations/[slug]` | Destination detail, with gallery and lightbox |
| `/experiences` | Experiences, labelled "Reported in Maasim" or "Travel inspiration" |
| `/culture` | Culture and food |
| `/stories` | Story search and category filters |
| `/stories/[slug]` | Story article |
| `/travel-guide` | Practical guide and FAQ |
| `/about` | Approach, verification checklist, photo credits |
| `/privacy`, `/accessibility` | Policies |
| `/sitemap.xml`, `/robots.txt` | SEO files |

## Project structure

```
src/
  app/          Routes, metadata, sitemap, robots, icon
  components/
    layout/     Header, mobile menu, search dialog, footer, back-to-top
    home/       Homepage sections
    destinations/ Destination card and browser
    stories/    Story card, browser, and article body
    shared/     Photo, gallery, tags, filters, FAQ, page header
  data/         All content as typed TypeScript
  lib/          Client-side search helpers
  types/        Content models
public/images/photos/  Locally stored, licensed photographs
```

Content is kept separate from the UI. To add a destination, story, or itinerary, add an entry to the matching file in `src/data/`. Pages, search, the sitemap, and related links pick it up automatically. Later, a CMS or database can replace these files as long as it returns the same types from `src/types/content.ts`.

## Content accuracy rules

- Every destination has a `status` (`verified`, `partial`, `placeholder`) and a `toVerify` list, both shown on the page.
- Experiences are labelled as either documented in Maasim or general inspiration.
- Itineraries are labelled as suggestions, with no invented times, prices, or transport.
- Events are sample entries clearly marked "Demonstration content".
- No fabricated reviews, ratings, quotes, statistics, or structured business data.
- Each photo records whether it was taken in Maasim. Photos from elsewhere around Sarangani Bay are labelled with their real location.
